# Чат на основе Green API

Веб-приложение для обмена текстовыми сообщениями через WhatsApp с использованием [Green API](https://green-api.com/). Пользователь авторизуется своими учётными данными инстанса, создаёт чат с конкретным номером и обменивается сообщениями прямо из браузера.

Дизайн интерфейса основан на веб-версии WhatsApp.

Сайт опубликован по ссылке: https://eirateufel.github.io/whatsapp_connect/

## Стек технологий

- **React** (Vite)
- **react-router-dom** - переходы между страницей авторизации и страницей чата
- **Green API** - отправка и получение сообщений WhatsApp
- Чистый CSS (без UI-библиотек)

## Функциональность

1. Пользователь переходит на сайт и вводит учётные данные: номер телефона, API URL, ID Instance, токен.
2. Пользователь вводит номер телефона получателя и создаёт новый чат.
3. Пользователь пишет текстовое сообщение и отправляет его.
4. Получатель отвечает в WhatsApp.
5. Пользователь видит ответ получателя в чате.

Получение сообщений реализовано через периодический опрос (`polling`) очереди уведомлений Green API (`receiveNotification` / `deleteNotification`), с фильтрацией — в интерфейсе отображаются только сообщения от текущего собеседника.

## Установка и запуск

Требуется Node.js (проверялось на версии 18+) и npm.

```bash
# Установить зависимости
npm install

# Запустить дев-сервер
npm run dev
```

После запуска приложение доступно по адресу, который выведет терминал.

Для входа понадобятся реальные данные активного инстанса Green API:

| Поле | Описание |
|---|---|
| API URL | Базовый адрес API, выданный Green API |
| ID Instance | Идентификатор инстанса |
| Токен | API-токен инстанса |

## Архитектурные решения

В ТЗ в качестве учётных данных упоминаются idInstance и токен. Для построения запросов к Green API этого недостаточно: также необходима **apiUrl**. Не смотря на то, что числа в idInstance и apiUrl могут совпадать, **в документации к API нет явного указания на то, что apiUrl может быть сгенерирована из idInstance для любых инстансов**, поэтому в интерфейс авторизации добавлено поле ввода apiUrl.

В ТЗ явно указано требование к **максимально простому интерфейсу с минимальным набором функций**. Там, где функциональность не была явно описана, выбор делался в пользу более простого решения. Ключевые примеры:

- **Данные авторизации не сохраняются между сессиями** (ни в `localStorage`, ни на сервере) и хранятся только в памяти приложения на время открытой вкладки.
- **Не отслеживаются сообщения, отправленные с других устройств того же аккаунта отправителя** (`outgoingMessageReceived` от Green API не обрабатывается), т.к. не описана синхронизация собственных сообщений с других клиентов WhatsApp.
